# 抖音无人直播技术方案

基于[直播辅助工具功能规划](直播辅助工具功能规划.md)与[个人直播辅助网站方案](个人直播辅助网站方案.md)，给出**无人值守直播/录播**的具体技术落地路径。全部基于已验证的开源项目，可自行部署、本地可控。

---

## 🎯 目标

- **无人值守**：无需人盯屏，自动开播/录制/互动
- **三合一**：录播循环、AI 弹幕互动、多平台推流
- **本地可控**：数据不经过第三方云，弹幕/礼物数据归自己

---

## 🏗️ 总体架构

```
                ┌────────────────────────────────────┐
                │            控制端（自建）            │
                │  StreamCap（录制）→ 本地存储/回放     │
                │  BarrageGPT（弹幕→AI→回复）          │
                └──────────────┬─────────────────────┘
                               │ OBS/RTMP 推流
                ┌──────────────┴──────────────┐
                │    mediamtx 流媒体服务器     │
                │  (RTMP→HLS/WebRTC 转分发)    │
                └──────────────┬──────────────┘
                   ┌───────────┼───────────┐
                   ↓           ↓           ↓
                抖音/直播平台   自建Web     归档存储
```

## 📋 三种落地模式

### 模式 A：录播循环（最简单）
1. 用 **StreamCap** 录制优质直播存档
2. OBS 里做「录像回放」场景，用 **mediamtx** 做推流/转分发
3. 定时或无人时切换回放流

### 模式 B：AI 弹幕无人直播
1. **BarrageGPT** 接入抖音弹幕 → 接大模型自动回复
2. **obs-backgroundremoval** 处理画面（背景虚化/替换）
3. OBS 推流，**StreamCap** 同时录制备份

### 模式 C：多平台分发
1. OBS 推一路 RTMP 到 **mediamtx**
2. mediamtx 转 HLS/WebRTC，自建 Web 页（对应[个人直播辅助网站方案](个人直播辅助网站方案.md)）
3. 各平台数据回流到自己后台做统计

---

## 📅 落地步骤

1. **第 1 周**：OBS + mediamtx 打通本地推流/拉流
2. **第 2 周**：StreamCap 跑通自动录制与定时归档
3. **第 3 周**：BarrageGPT 接弹幕 + AI 回复，灰度测试
4. **第 4 周**：组合成完整无人直播流程，压测稳定性

---

## ⚠️ 风险与合规

- 无人直播、弹幕 AI 代答涉及**平台规则**：开播前务必核对抖音等平台的《直播行为规范》，避免违规封号
- 录制他人直播用于再分发，注意版权与平台授权
- 建议只对**自己的账号/授权内容**做自动化和归档
