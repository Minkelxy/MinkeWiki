# LoRa监测产品化路线：从Demo到可交付产品

承接[落地优先级推荐](落地优先级推荐.md)的第一优先级，把 LoRa 气象监测从"能跑的技术 Demo"做成**能卖、能维护、能续费的产品**。本文是技术侧的产品化路线：硬件量产、固件运维、平台运营、交付售后四层，每层给出「现状 → 改造清单 → 落地里程碑」。

> 配套商业文档：定价见[财务与定价模型](财务与定价模型.md)，销售见[农业获客与销售](农业获客与销售.md)，宣传见[品牌与宣传](品牌与宣传.md)。

---

## 一、产品化的判断标准：不用你到场的设备

Demo 和产品之间没有模糊地带，用**三个问题**检验：

| # | 检验问题 | Demo 的表现 | 产品的要求 |
|---|---------|------------|-----------|
| 1 | 客户断电一周，设备能自愈吗？ | 网关重启后节点失联，要人上门 | 自动重连 + 补发缓存 + 上报事件 |
| 2 | 10 台节点坏了 1 台，能远程定位吗？ | 看不出哪台、什么原因 | 在线率/最后上报时间/错误码可查 |
| 3 | 平台升级或重启，会不会掉设备？ | 网关地址变就断 | 自动重连，业务无感 |

> 一句话：**客户报障的每一分钟，都是你的成本**。产品化 = 把"要上门才能解决的问题"逐个变成"远程就能解决"。

## 二、硬件层：从样机到可批量复制

**现状**：单节点 ≈ 265 元、手工组装、开发板堆叠、裸板或简陋防护。

**改造清单**（按优先级排）：

| 项 | 现状 | 改造目标 | 关键点 |
|----|------|---------|--------|
| 电路板 | 开发板堆叠 | 量产 PCB：集成电源管理、锂电池充电、LoRa 模块、传感器接口 | 参考[PCB设计入门](../制作/PCB设计入门.md)的做法；把易损接口做成可插拔，方便现场换传感器 |
| 结构防护 | 裸板/简陋壳 | IP65+ 外壳、防水接头、太阳能板支架 | 农业大棚重点防**尘、凝露、虫**，比防水更常见；外壳开孔处全用防水接头 |
| 电池安全 | 普通锂电池 | 带 BMS 的电芯 + 低温充电保护 | **低于 0℃ 禁止充电**（宁夏冬天是硬需求）；出货走 UN38.3 运输报告 |
| 出厂测试 | 人工点检 | 测试夹具：自动烧录 + 校准 + 功能测试 | 见下方「出厂测试项」，把测试标准化，组装可以靠手工，测试必须靠流程 |
| 防雷 | 无 | 电源口 TVS + 信号口保护 | 农田空旷地防感应雷，成本几块钱，售后省一大截 |

**量产路径**：不要直接上量产。先**手工小批（10-20 台）**跑通交付和运维，确认客户真在续费，再找 SMT 贴片厂 + 组装测试外包。顺序是「先卖出去，再省成本」。

**出厂测试项清单**（每台必测）：
- [ ] 供电：太阳能/电池/市电三种模式都能开机
- [ ] 采集：各传感器读数在合理区间（温湿度、光照、土壤）
- [ ] 通信：LoRa 入网成功、数据到达网关
- [ ] 断线重连：关网关 30 秒重开，节点自动重连并补发
- [ ] 低电量：模拟低压，触发低电量事件上报
- [ ] 老化：整机通电 24h 无死机（抽查，不必每台）

## 三、固件层：能远程运维的三个能力

现有方案已规划「远程配置 + OTA」（见[项目文档](../制作/LoRa气象监测/项目文档.md)），本轮重点是**把这三个能力做扎实，并补健壮性**：

1. **远程配置（下行通道）**
   采集周期、阈值、上报间隔要能下发。LoRa 下行帧带宽有限，配置走「网关 → 节点」的下行帧，平台侧做一个「配置下发 + 确认回执」，失败自动重试。

2. **固件 OTA（升级通道）**
   LoRaWAN 生态有 FUOTA（Firmware Updates Over The Air）规范（LoRa 联盟标准），本质是分片传输 + 校验 + 重启切换。参考实现可见 [beegee-tokyo/WisBlock-Toolbox](https://github.com/beegee-tokyo/WisBlock-Toolbox)（RAK WisBlock 的 OTA DFU 组件）。**小团队不必先上 FUOTA**——自建「分片下发 + CRC 校验 + 双分区」的简化 OTA 就够，USB 串口升级留作兜底。关键决策：**升级失败必须能回滚到旧固件**，否则一台变砖的节点 = 一趟上门。

3. **健壮性（自愈四件套）**——产品化的真正门槛：
   - **看门狗**：主循环死锁自动复位
   - **断线重连 + 缓存补发**：网关重启后自动重连，断线期间数据存本地，连上后补发（带时间戳，别混在实时数据里）
   - **低电量优雅降级**：电量低 → 上报低电量事件 → 降采集频率 → 继续存活而不是直接关机
   - **上电自检 + 错误码**：传感器失效时上报错误码（如 `SENSOR_TEMP_FAIL`），客户报修时你远程就知道带什么零件

## 四、平台层：设备管理与服务

**选型**：自建 [thingsboard/thingsboard](https://github.com/thingsboard/thingsboard)（开源 IoT 平台，设备管理 + 数据采集 + 可视化 + 告警，22k+ star）仍是性价比首选；中文学习资料可直接看 [IoT-Technology/IoT-Technical-Guide](https://github.com/IoT-Technology/IoT-Technical-Guide)（从零搭建 IoT 平台 + Thingsboard 源码分析）。网络侧如果用标准 LoRaWAN，可对接 [chirpstack/chirpstack](https://github.com/chirpstack/chirpstack) 或 [gotthardp/lorawan-server](https://github.com/gotthardp/lorawan-server)（私有 LoRaWAN 网络服务器，轻量，适合小团队）。

**功能上必须补齐的四件事**：

| 功能 | 为什么必须 | 落地 |
|------|-----------|------|
| 多租户隔离 | 合作社 A 不能看到 B 的数据 | ThingsBoard 的租户/设备组模型，每个客户一组 |
| 告警推送 | 阈值、断线、低电量要主动通知 | 告警规则 → 微信/短信推送（农业老板不看后台） |
| 数据导出 | 客户要月度报表当"购买凭证" | 平台导 CSV/PDF 月报，省得你手工做 |
| 在线率看板 | **续费的核心证据** | 客户一眼看到"设备在线率 99%"，比任何销售话术都硬 |

> 注意：**告警推送别只发后台**。农业客户的核心诉求是"棚里异常了要有人告诉我"，微信/短信通道是标配，不是加分项。

## 五、交付与售后 SOP（决定续费）

商业侧已有交付流程（见[商业方案](LoRa监测产品商业方案.md)），这里补**技术侧的执行细节**：

1. **部署 SOP**：勘测（点位信号/太阳能朝向）→ 安装 → 上线校验（看板见数据）→ 客户验收单签字
2. **远程诊断流程**（客户报障的固定动作）：
   ```
   接报障 → 查平台：该节点在线率/最后上报时间
       ├─ 最后上报超时 → 判定节点或网关掉线 → 远程重启网关 → 看是否自动重连
       ├─ 有错误码 → 按错误码清单定位（传感器坏/电池/通信）→ 带件上门
       └─ 无异常 → 让客户看现场供电/遮挡
   ```
3. **SLA 承诺写进合同**：工作日 4 小时响应、远程诊断免费、上门按次收费（见[合同与交付模板](合同与交付模板.md)）
4. **季度巡检 = 增值入口**：巡检顺带推"加传感器"（土壤、水势），加传感器 = 加订阅额
5. **每次交付沉淀案例**：复用[品牌与宣传](品牌与宣传.md)的"背景-方案-效果"模板，一单一个案例页

## 六、8 周里程碑（从 Demo 到首个交付）

| 周 | 任务 | 产出 |
|----|------|------|
| W1-2 | PCB 改版 + 外壳打样 + 测试夹具 | 3 台可批量复制的样机 + 出厂测试项清单 |
| W3-4 | 固件 OTA + 断线重连/补发 + 参数下发 | 远程升级 + 自愈演示 |
| W5-6 | 平台多租户 + 告警推送 + 在线率看板 | 可演示的客户隔离平台 |
| W7-8 | 试点部署 2-3 节点 + SOP 文档 | 首个案例 + 验收单模板 |

## 七、本轮项目推荐：做「自愈型节点」演示

**推荐做什么**：给现有 LoRa 节点加**断线重连 + 自恢复 + 状态事件上报**（POWER_LOSS / REJOIN / LOW_BATTERY 三类事件帧），平台加**在线率 + 最后上报时间**看板，做一段「节点断电一周 → 网关重启 → 节点自动自愈并补发数据」的实拍演示。

**为什么值得做**：
- 这是"Demo"和"产品"最本质的分界线——上面三个检验问题，第一个都不过关就没法谈交付；
- 一次开发同时喂饱硬件（出厂测试项）、固件（自愈）、平台（在线率看板）三条线，是产品化的**最小闭环**；
- 客户（农业老板）最关心的就是可靠性，这是最能打动人的卖点，也是投标/谈试点的硬材料。

**具体怎么做**：
1. 固件：加看门狗 + 断线缓存重发 + 事件帧（带时间戳）
2. 平台：设备详情页加"在线率 / 最后上报时间 / 事件记录"
3. 实测：拔掉一台节点电源 → 重启网关 → 观察自愈与补报，录视频

**产出**：1 分钟演示视频 + 在线率看板截图 → 进案例集，作为[农业获客与销售](农业获客与销售.md)里"试点换案例"的第一张牌。
