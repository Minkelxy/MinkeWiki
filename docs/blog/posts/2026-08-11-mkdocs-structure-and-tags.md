# MkDocs 站点结构优化与标签系统实践

内容多了之后，个人知识库的导航开始失控：14 个平铺栏目、首页手工索引老是过时、每天 +1 的日记列表把侧边栏塞满。这篇记录我做的结构优化与标签系统改造。

## 一、结构：从平铺到分类

第一步是把顶层导航归类成四个大类：

- **技术**：知识库 / 制作项目 / 个人项目 / 游戏
- **创作**：音乐 / 剧本 / 观影 / 视频 / 博客
- **生活**：社交 / 行动记录 / 健身 / 小屋装修
- **事业**：创业

顶部 tab 从 14 个降到 6 个，侧边栏层次立刻清晰了。

## 二、统一入口：README.md

原来栏目入口命名混乱（`目录.md`、`制作目录.md`、`README.md`、`index.md` 混用）。MkDocs 会把子目录下的 `README.md` / `index.md` 当作目录首页（渲染 URL 为 `目录/`），所以统一成 `README.md`，并给旧路径配置了 `redirects` 重定向，旧链接不会 404。

## 三、卡片首页

首页原来是手工维护的链接列表，加一篇文档就要改一次。重写成卡片式导航（CSS grid），每栏目一张卡片，带图标和简介，hover 有浮起动效。

> ⚠️ 踩坑：卡片用纯 HTML 写 `<a href>`，MkDocs 的 `md_in_html` **不会转换**纯 HTML 里的链接——href 写成 `.md` 会 404。必须写渲染后的 URL（`README.md` → `目录/`），或者干脆用 markdown 语法 `[文本](路径)` 让 MkDocs 自动转换。

## 四、标签系统

Material 的 `tags` 插件一直配着但没用。给文档 frontmatter 加 `tags:` 字段后，`tags.md` 自动生成标签索引，跨栏目聚合——点「电机控制」，知识库笔记和制作项目能一起拉出来。

```yaml
---
tags:
  - 电机控制
  - FOC
---
```

## 五、侧边栏与美化

- 关掉 `navigation.expand`，侧边栏默认折叠，只显示顶层题目，点击展开
- `extra.css` 定制了引用块、表格、代码块、卡片样式，全站观感统一
- 健身数据页用 ECharts 加了体重/训练量趋势图

## 小结

结构优化的核心思路：**让导航自己长出来，而不是手工维护**。分类、统一入口、标签系统，都是把"人工维护"变成"约定 + 自动生成"。内容越多，这套结构越省力。
