# 三国群英传2Re 存档系统设计

[开发方案](三国群英传2Re开发方案.md)说"武将数据放 JSON（便于存档修改器互通）"——本文把**存档系统**落成专文：格式、时机、多槽、坏档防护、Godot 落地。

> 一句话：存档不只是"存文件"——**存得稳、读得出、坏了能救**，是玩家体验的分水岭。

---

## 一、存档系统要解决什么

- **存档 = 游戏进度的持久化**（武将 / 兵力 / 城池 / 剧情进度）
- 玩家要能：**随时存、随时读、进度不丢、存档不坏**
- 复刻加分项：原版的**存档修改器**是玩家圈文化——设计成"好改"（见[开发方案](三国群英传2Re开发方案.md)）

## 二、数据结构（JSON，与逻辑分离）

**分两层**：
```
存档 = 玩家进度（武将 / 兵力 / 城池 / 物品）+ 世界状态（时间 / 事件标记）
```

**JSON 示例**：
```json
{
  "version": 1,
  "player": { "gold": 500, "name": "玩家" },
  "armies": [ { "general_id": 12, "soldiers": 8000, "pos": [3, 5] } ],
  "cities": [ { "id": 1, "owner": 12 } ],
  "events": { "battle_won": true }
}
```

**三条关键约定**：
1. **带 `version` 字段**——升级后旧档可迁移（版本不匹配给"升级提示"而非直接失败）
2. **加校验和**（CRC / 简单哈希）——防损坏/防意外篡改导致坏档
3. **别序列化运行时对象**——Godot 对象引用会乱，用**纯数据 DTO**（见第三节）

## 三、保存与读取（Godot 落地）

- **存文件**：`user://`（用户数据目录，跨平台安全），JSON 写读
- **读档校验**：`version` 检查 + 数据合法性（武将存在？兵力在合理范围？）
- **坏档处理**：校验不过 → 提示 + **保留原文件备份**，别直接清空
- **异步保存**（避免卡顿，保存瞬间的游戏停顿很出戏）

## 四、存档时机（自动 + 手动）

| 时机 | 说明 |
|------|------|
| **手动** | 菜单存 / 读 |
| **自动**：回合结束 | 大地图阶段进度 |
| **自动**：关键战斗前 | 避免"打完一仗死机白打" |
| **自动**：进入新章节 | 主线里程碑 |

- **多存档槽**：至少 3 槽——防止坏档 / 手滑覆盖

## 五、与存档修改器互通（复刻的加分项）

- 原版有**存档修改器文化**（开发方案已提，玩家爱改武将/兵力）
- 设计取向：**明文 JSON 可改** + 存档带"已修改"标记
  - 太严（加密/强校验）= 改不了，丢玩家圈
  - 太松（无痕）= 随意作弊
  - **推荐**：明文可改，标记"已修改"——进度不破坏，但系统可识别（如排行榜不计入）

---

## 六、本轮项目推荐：做「存档读写模块 + 坏档防护」

**推荐做什么**：给三国群英传2Re 写一个存档模块（`save / load / validate / 多槽`），跑通"**战斗 → 存档 → 读档 → 进度不丢**"，并做**坏档防护演示**（改坏一个字节 → 提示 + 备份恢复）。

**为什么值得做**：
- 存档是**任何游戏的必需品**，[开发方案](三国群英传2Re开发方案.md)已规划 JSON 数据，正好落地；
- 存档模块做一次，后面内政 / 剧情系统都靠它——**数据地基**；
- **坏档防护是玩家体验的分水岭**（"存了读不出"= 灾难），比功能本身更值钱。

**具体怎么做**：
1. 定义存档 DTO（带 `version` + 校验和，见第二节）
2. Godot 写读 `user://` JSON + 多槽位（见第三节）
3. 加校验：version / 数据合法性 / **坏档备份恢复**
4. 实测：战斗存读一次 + 改坏文件看防护

**产出**：一个可复用存档模块 + 坏档防护演示 → 进三国群英传2Re，也是后续内政 / 剧情系统的数据地基。
