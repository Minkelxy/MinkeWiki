# 坐标映射与输入注入

CV 自动化管线后半段：把识别框变成**精准操作**。配合[屏幕捕获](屏幕捕获与性能优化.md)（前半段）与[YOLO训练实战](YOLO训练实战.md)（识别），补全整条链路。

---

## 一、坐标映射（识别框 → 屏幕坐标）

### 核心换算

```
屏幕坐标 = 识别框中心 × 缩放比 + 窗口偏移
```

- **识别图**是抓屏的图，**目标屏幕**是真实窗口/全屏——两者尺寸可能不同
- 关键处理：
  - **窗口偏移**：目标窗口不在 (0,0) 时，加上窗口位置
  - **缩放比**：抓屏图缩放处理过，就要乘回去（识别图尺寸 / 实际截图尺寸）
  - **DPI 缩放**：Windows 下显示器缩放会影响坐标，统一换算到物理像素

### 常见坑

- 全屏 vs 窗口化模式坐标不一致 → 固定用一种模式测试
- 多显示器：目标窗口可能不在主屏，偏移量要算

## 二、输入注入方案

| 方案 | 优点 | 风险/成本 |
|------|------|-----------|
| **驱动级模拟**（如 IbInputSimulator） | 真实、难检测 | 需安装驱动 |
| 系统级 API（SendInput/mouse_event） | 简单、零依赖 | 部分游戏可检测 |
| 硬件执行（ESP32 等真实 HID） | 完全绕开软件层 | 需硬件、延迟略高 |

> 推荐：**先系统级 API 跑通，被检测或精度不够再上驱动级；硬件方案留给逆战未来的 Minke 层。**

## 三、精度与时机

### 提前量（目标移动预测）

- 目标在动时，瞄准点要加**提前量**：`目标位置 + 目标速度 × 输入延迟`
- 简单做法：记录目标最近两帧位移，估算下一帧位置

### 移动平滑

- 别一次性跳到位（太生硬、易被怀疑）：分成几小步移动
- 或按距离调整速度：远快近慢

### 时序配合

- 输入频率 ≠ 识别频率：识别 15-20FPS，输入可更高频
- 每次识别结果加**置信度门限**再执行，别误触

## 四、实测与调参

1. 全链路打点：识别输出坐标 → 输入生效，测实际延迟
2. **命中率测试**：固定场景跑 N 次，统计命中率
3. 调参点：提前量大小、平滑步数、置信度阈值

> 目标：全链路 <100ms（见[屏幕捕获](屏幕捕获与性能优化.md)延迟预算），命中率达标再谈优化。

## 五、合规提醒

- 输入注入类自动化涉及游戏服务条款与反作弊，**仅在合规场景使用**（单机/学习/被允许环境）
- 硬件宏同样适用（见[逆战未来](逆战未来/逆战未来.md)项目文档的免责声明）
