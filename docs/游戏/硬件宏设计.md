# 硬件宏设计

用**独立硬件**执行宏指令（真实 HID 输入）——对应[逆战未来](逆战未来/逆战未来.md)的 Minke 硬件层，以及制作目录里的"硬件宏"项目。

---

## 一、什么是硬件宏（vs 软件宏）

| 软件宏 | 硬件宏 |
|--------|--------|
| 用程序模拟键鼠 | 独立硬件产生**真实 HID 输入** |
| 依赖系统/易被检测 | 完全绕开软件层 |
| 零成本 | 需硬件 |

> 硬件宏的本质：**一台小 USB 设备，模拟成键盘/鼠标**，把宏指令变成真实输入事件。

## 二、硬件组成

| 模块 | 说明 |
|------|------|
| 主控 | ESP32-S3（原生 USB OTG，可枚举 HID） |
| HID 设备 | 枚举成 USB 键盘 + 鼠标 |
| 触发接口 | 按键直连 或 上位机下发（串口/网络） |
| 与策略层通信 | 串口（简单）或 Wi-Fi（远程） |

> 对应逆战未来架构：**Minke = 硬件执行层**，接收 NZM_CMD 策略层的指令执行输入。

## 三、HID 实现要点

- **描述符**：键盘用 8 字节输入报告（修饰键 + 6 键位），鼠标用 4-5 字节（x/y/滚轮/按键）
- 枚举即插即用，主机识别为普通键鼠
- 上报频率：USB 全速默认 1kHz 轮询足够

## 四、宏执行流程

```
上位机（NZM_CMD 策略层）→ 下发宏指令（串口/网络）
  → 硬件解析宏 → 按序执行输入（键/鼠/延时）
  → 主机收到真实 HID 输入
```

- 宏指令格式自定（如 `KEY W, 50ms, KEY S, 30ms`）
- 硬件端用**队列 + 定时器**按序执行，保证时序

## 五、延迟与精度（关键参数）

| 参数 | 目标 | 说明 |
|------|------|------|
| 指令延迟 | < 1ms | 上位机→硬件的传输延迟 |
| 按键间隔精度 | ±1ms | 用硬件定时器，别用软件 sleep 堆 |
| 上报抖动 | 小 | 别让宏时序忽快忽慢 |

> 宏的时序**必须在硬件端保证**——软件 sleep 不稳定，会抖动。
