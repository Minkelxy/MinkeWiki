# 游戏自动化调试与测试

自动化管线**跑不通、跑不准**怎么办——系统调试方法。承接[逆战未来推进路线](逆战未来推进路线.md)的分层验证。

---

## 一、调试思路（先定位，别瞎试）

```
抓屏 → 识别 → 坐标 → 输入
```

- **分环节定位**：先确定是哪个环节出问题，再改
- **打点**：每环节记录耗时 + 关键值（识别框坐标、置信度）
- 一次只改一个变量（和[硬件调试](../制作/硬件调试入门.md)同理）

## 二、分环节检查清单

| 环节 | 检查 | 常见问题 |
|------|------|---------|
| 抓屏 | 截到的图对吗？ | 黑屏/错窗口/分辨率不对 |
| 识别 | 框对不对、置信度高吗？ | 误检、漏检、框抖动 |
| 坐标 | 换算后点对地方吗？ | 窗口偏移/DPI 算错 |
| 输入 | 输入生效了吗？ | 窗口无焦点/被拦截 |

> 每环节用一个"已知正确答案"的场景测试——**对不上就是这环节的问题**。

## 三、日志与可观测（必备）

- **每步留日志**：时间戳 + 识别结果 + 坐标 + 执行动作
- **截图存证**：识别帧/执行帧存图，出错时能回看"当时画面是什么"
- 事后能回放 → 问题可复现 → 好排查

## 四、回归测试（跑得多才稳）

- **固定场景**：同一场景跑 N 次（如 100 次）
- **统计指标**：命中率、误报率、平均延迟
- 每次改动后**重跑回归**，确认没弄坏别的

| 指标 | 含义 | 目标参考 |
|------|------|---------|
| 命中率 | 正确识别+执行的占比 | >80% |
| 误报率 | 误操作占比 | 越低越好 |
| 平均延迟 | 全链路耗时 | <100ms |

## 五、常见问题与处理

| 问题 | 可能原因 | 处理 |
|------|---------|------|
| 识别抖动 | 阈值太低/目标小 | 提阈值、加跟踪（上一帧位置优先） |
| 偶尔没执行 | 输入被吞/无焦点 | 执行前确认窗口焦点、加重试 |
| 坐标总偏 | 缩放/DPI 没算对 | 用"多点校准"修正偏移 |
| 时快时慢 | 线程调度不稳 | 固定频率识别、别动态调速 |
