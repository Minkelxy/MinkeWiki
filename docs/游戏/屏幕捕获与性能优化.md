# 屏幕捕获与性能优化

CV 自动化管线（[技术基础](游戏自动化技术基础.md)）的**第一步也是性能瓶颈**：怎么高效抓屏，在低延迟和低 CPU 之间取平衡。

---

## 一、为什么抓屏是瓶颈

- 游戏画面高速变化，**全屏逐帧抓取开销大**（一帧 1080p 约 8MB）
- 抓屏慢 → 识别慢 → 操作慢，整条链路的延迟预算全被它吃掉
- 目标：**延迟低 + CPU 占用低**，别让自动化工具自己卡游戏

## 二、抓屏方案对比

| 方案 | 延迟 | CPU 占用 | 适用 |
|------|------|---------|------|
| **DXGI Desktop Duplication**（Windows） | 低 | 低 | 高性能、正式版 |
| mss / PIL（Python 截图库） | 中 | 中 | 快速原型、起步 |
| 游戏内 hook/注入 | 极低 | 低 | **不推荐**（反作弊风险极高） |

> 推荐路线：**初版用 mss 快速跑通**，确认识别逻辑后再上 DXGI 提性能。

## 三、性能优化手段（按收益排序）

1. **ROI 裁剪**：只抓战斗/目标区域，别抓整个屏幕——收益最大
2. **降帧率**：识别 15-20 FPS 足够，别每帧都抓（游戏画面 60FPS 但识别用不上）
3. **缩放**：把抓到的图缩到识别所需的最小尺寸（如 640 宽），识别更快
4. **流水线异步**：抓屏线程 + 识别线程并行，抓下一帧的同时识别上一帧

## 四、延迟预算

全链路目标：**抓屏 → 识别 → 输入 < 100ms**

| 环节 | 预算 |
|------|------|
| 抓屏 | 10-30ms |
| 识别（YOLO 小模型） | 30-50ms |
| 坐标映射 + 输入注入 | 5-10ms |

> 抓屏超预算优先上 DXGI + ROI；识别超预算换更小模型或降尺寸。

## 五、推荐落地

1. **第 1 步**：mss 抓屏 + ROI 裁剪，跑通识别
2. **第 2 步**：测各环节耗时（打点计时），看瓶颈在抓屏还是识别
3. **第 3 步**：瓶颈在抓屏 → 上 DXGI；在识别 → 缩尺寸/换小模型
4. **第 4 步**：抓屏与识别改并行流水线
