# 游戏自动化策略层设计（NZM_CMD 决策大脑）

承接[逆战未来推进路线](逆战未来推进路线.md)的**第 2 步：策略闭环**。三层架构里，识别层（CV）回答"屏幕上有什么"，策略层（NZM_CMD）回答"接下来干什么"，执行层（Minke/系统输入）负责"怎么动"。本文专讲**决策层怎么设计**——这是目前唯一还没有专文的一层。

> 核心一句话：**决策层只看"世界状态摘要"，不碰原始图像**。把识别结果先归一化成结构化数据，决策逻辑才写得好、调得动、测得准。

---

## 一、策略层要解决的三件事

1. **整理**：把 CV 识别结果归化成「世界状态」（当前帧摘要）
2. **决策**：按世界状态 + 游戏规则决定「做什么」
3. **执行跟踪**：把决策转成命令，并跟踪结果（成功/失败/超时）

> 识别层给的是像素和框，策略层要的是**结构化事实**：屏幕上有 2 个敌人、1 个血包、自己血量 60%、处于战斗阶段。事实不清，决策无意义。

## 二、决策模型：状态机管大局 + 每状态内用优先级规则

| 模型 | 特点 | 适合 | 参考实现 |
|------|------|------|---------|
| **有限状态机 FSM** | 阶段清晰、事件驱动、易调试 | 对局宏观流程：加载→开局→战斗→结算 | [rust-bakery/machine](https://github.com/rust-bakery/machine)（Rust 类型安全状态机） |
| **行为树 BT** | 适合优先级/并行决策、节点可复用 | 单个状态内的动作选择（多目标先打谁、先做哪件事） | [BehaviorTree/BehaviorTree.CPP](https://github.com/BehaviorTree/BehaviorTree.CPP)、[Sollimann/bonsai](https://github.com/Sollimann/bonsai)（Rust 行为树） |
| 简单规则 + 优先级 | 零依赖、冷启动最快 | 先跑通闭环再说 | — |

**推荐组合**：**FSM 管大局（对局阶段切换）+ 每个状态内用优先级规则/行为树选动作**。

> 别一开始就上行为树框架。先用 `if` 链 + 优先级列表写死，等规则多到难以维护时再引入 BT——框架是给"规则爆炸"准备的，不是给"跑通闭环"准备的。

## 三、核心数据结构（先定接口，再写逻辑）

```
识别结果（CV）→ WorldState（策略输入）→ 决策 → Command（执行输入）
```

**世界状态 WorldState**（每帧更新）：

```rust
struct WorldState {
    time: u64,                       // 帧时间戳
    phase: GamePhase,                // 对局阶段（FSM 当前态）
    targets: Vec<Target>,            // 识别到的目标
    hp: f32, skill_cd: HashMap<SkillId, u32>,  // 自身状态
}

struct Target {
    kind: TargetKind,                // 敌人 / 血包 / 道具…
    pos: Vec2,                       // 屏幕坐标（已换算，见[坐标映射]）
    confidence: f32,                 // 置信度
    age: u32,                        // 连续出现帧数（防抖）
}
```

**命令 Command**（决策输出，显式枚举）：

```rust
enum Command {
    Move { pos: Vec2 },
    Attack { target_id: u32 },
    PickUp { item_id: u32 },
    Wait { ms: u32 },
    Nothing,            // 显式"无事可做"——日志里能区分两种情况
}
```

**三条关键约定**：
1. **Target 必须带 confidence + age**：单帧识别不可信，连续 N 帧出现才当真（防抖动/防误识别）。这是稳定性的第一道闸。
2. **`Command::Nothing` 要显式**：日志能区分"没识别到"和"识别到但选择不动"——两种是完全不同的 bug。
3. **所有字段带时间戳**：决策层才能回放复盘。

## 四、核心决策逻辑：五个必写模块

| 模块 | 要解决的 | 落地建议 |
|------|---------|---------|
| **目标优先级/威胁评估** | 多个目标出现先打谁 | 评分 = 威胁系数 × 距离权重 × 置信度。先用写死规则（近的高分），别过早抽象 |
| **冷却管理** | 动作能不能现在发 | 技能 CD 表，决策前先查"这个动作此刻可用吗" |
| **容错与重试** | 命令没生效/识别失败 | 同一决策最多重试 N 次，超限放弃并上报——防死循环刷命令 |
| **超时与恢复** | 状态卡住 | 任何状态卡超 T 秒 → 回到安全状态复位。和硬件看门狗同理，是"自愈" |
| **决策频率与节流** | 别每个识别帧都发命令 | 决策频率 = 识别频率（15-20 FPS 足够），输入注入可更高频；命令带节流 |

> 参考一个真实的 CV bot 最小实现：[paulonteri/play-game-with-computer-vision](https://github.com/paulonteri/play-game-with-computer-vision)（用 CV 玩 City Island 5，含决策循环，适合照结构拆）。

## 五、决策可观测性（调试核心，必须内置）

没有日志，策略层一出错根本分不清是**识别错**还是**逻辑错**：

- **决策日志**：每帧一行 `time | 世界状态摘要 | 决策 | 命令`，追加写文件
- **回放**：把日志叠在录屏上，复盘"它为什么这么干"
- **计数器**：每个决策类型计次（如 `Attack 发出 342 次 / 命中 118 次`），用数据说话，别靠感觉调参

## 六、里程碑（接推进路线的第 2 步）

| 里程碑 | 内容 | 验收 |
|--------|------|------|
| P1 | WorldState + 决策日志上线 | 录屏能叠日志回放 |
| P2 | 一个完整决策闭环 | 识别到 X → 决定 → 发命令，无人干预跑通一次完整操作 |
| P3 | 冷却/容错/超时三件套 | 卡住能自恢复，不重复刷命令 |

## 七、本轮项目推荐：做「决策日志回放器」

**推荐做什么**：给 NZM_CMD 加统一的**决策日志**（每帧 WorldState 摘要 → 决策 → Command），并做一个简单的**回放工具**（把日志逐帧叠在录屏上，标注每个决策的依据）。

**为什么值得做**：
- 这是"策略层闭环"的**调试地基**——没有它，策略层一上线你就在盲飞，识别错还是逻辑错根本分不清；
- 一次投入，后面每个闭环（冷却/容错/行为树）都靠它验证，直接对应推进路线的 M2 验收（"完整操作无人干预跑通"）；
- 让"决策"第一次**可演示、可解释**——比任何代码都更说明系统在思考。

**具体怎么做**：
1. 定义 `WorldState` / `Command` 两个结构体（见第三节），CV 层输出先转成 WorldState
2. 加决策日志：每帧一行，追加写文件
3. 简单回放：录屏 + 用时间戳把日志同步叠加上去（可先手工逐帧对齐）
4. 跑一个场景：识别 → 决策 → 动作，录下"带决策标注"的完整过程

**产出**：一段「识别→决策→动作」全程带决策标注的演示视频 + 决策计数器数据 → 直接进[逆战未来推进路线](逆战未来推进路线.md)的 M2 里程碑，也是向别人解释这套系统最直观的材料。
