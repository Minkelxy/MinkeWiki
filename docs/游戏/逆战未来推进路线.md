# 逆战未来 推进路线

基于逆战未来的**三层架构**（Minke 硬件执行层 / NZM_CMD 策略层 / CV 识别层），推荐推进顺序与各层里程碑。核心原则：**先打通最小闭环，再逐层加复杂度，别三线并行。**

---

## 一、三层架构回顾

| 层 | 载体 | 职责 |
|----|------|------|
| **CV 识别层** | OpenCV/YOLO | 截图 → 识别目标 |
| **NZM_CMD 策略层** | Rust | 决策 → 输出指令 |
| **Minke 硬件层** | ESP32-S3 | 执行真实输入 |

对应你已写的技术文档：CV 管线的抓屏/识别/坐标输入，正好是三层的软件侧铺垫。

## 二、推荐推进顺序

```
第 1 步：CV 最小闭环（纯软件）
第 2 步：接入 NZM_CMD 策略
第 3 步：接硬件层 Minke
```

### 第 1 步：CV 最小闭环（最重要，先做）

- 用[抓屏](屏幕捕获与性能优化.md) → [YOLO 识别](YOLO训练实战.md) → [坐标输入](坐标映射与输入注入.md)，**先走系统级输入**跑通"识别→操作"
- 里程碑：单场景识别 + 输入**命中率达标**（如 >80%）
- 别碰硬件——先验证**识别和逻辑对不对**

### 第 2 步：接入 NZM_CMD 策略层

- 把 CV 结果喂给 Rust 策略，做**一个决策闭环**（如：识别到 X → 决定怎么做 → 发出指令）
- 里程碑：一个完整"识别-决策-动作"闭环，无人工干预跑通

### 第 3 步：硬件层 Minke

- 系统级输入换 ESP32 硬件输入，验证命令通路
- 里程碑：软件指令 → 硬件真实输入生效，延迟达标

> **别一上来就三线并行**：先纯软件验证逻辑，再一层层换成硬件——每层的问题都好定位。

## 三、验证顺序建议

| 顺序 | 验证点 |
|------|--------|
| 先 | 单场景识别命中率（CV） |
| 再 | 决策闭环正确性（策略） |
| 后 | 硬件命令通路 + 延迟（硬件） |

## 四、里程碑与验收

| 里程碑 | 内容 | 验收 |
|--------|------|------|
| M1 | CV 识别稳定 | 单场景命中率 >80% |
| M2 | 策略闭环 | 完整操作无人干预跑通 |
| M3 | 硬件接入 | 全链路延迟达标 |

## 五、风险与合规

- 先小步验证再扩大范围，避免"全链路通了但识别不准"难排查
- 输入注入与硬件宏涉及游戏反作弊，**仅在合规场景使用**（见[坐标映射与输入注入](坐标映射与输入注入.md)免责）
