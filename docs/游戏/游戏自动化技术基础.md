# 游戏自动化技术基础

本文梳理游戏自动化的核心技术管线，作为[游戏自动化开源参考](游戏自动化开源参考.md)的工具配套，讲清「识别什么 → 怎么识别 → 怎么把结果变成操作」的完整链路。

---

## 一、三条实现路线

| 路线 | 原理 | 优点 | 缺点 | 适用 |
|------|------|------|------|------|
| **内存/注入** | 读进程内存、hook 函数 | 精准、快速 | 易被反作弊检测 | 单机/无反作弊 |
| **计算机视觉（CV）** | 截图 → 识别 → 模拟输入 | 不碰进程，隐蔽 | 速度较慢、受画面影响 | 通用、本方案主推 |
| **硬件外设** | 独立硬件执行输入 | 完全绕开软件层 | 需专门硬件 | 合规场景 |

> 「逆战未来」项目采用 **CV + 硬件执行** 双路线，即下面的管线。

---

## 二、CV 自动化管线

```
屏幕捕获 → 预处理 → 目标识别 → 坐标映射 → 输入注入
```

### 1. 屏幕捕获

- 捕获整屏或指定窗口区域，形成图像帧
- 关键点：**帧率**（通常 10-30 FPS 够用）、**窗口缩放**（需换算 DPI/缩放比）
- 工具：OpenCV 读帧；Python 侧可用 mss/pyautogui；Windows 上追求帧率可用 DXGI 抓屏

### 2. 预处理

- 转灰度/二值化、裁剪 ROI（感兴趣区域）、尺寸归一化
- 目的：降低计算量、提高识别稳定性和速度

### 3. 目标识别（核心）

**模板匹配（Template Matching）**——适合固定图标/UI：

- `cv2.matchTemplate` 在多分辨率下做滑动匹配
- 优点：无需训练，秒级上手
- 缺点：对旋转/缩放/光照敏感，只适合界面相对固定的场景

**深度学习检测（YOLO 系）**——适合动态、多变目标：

| 开源项目 | Star | 说明 |
|---------|------|------|
| [ultralytics/ultralytics](https://github.com/ultralytics/ultralytics) | 60.2k | YOLOv8/YOLO11 目标检测，实时性好，可导出轻量模型 |
| [HumanSignal/labelImg](https://github.com/HumanSignal/labelImg) | 25.1k | 标注工具，制作训练数据集 |

- 需要先标注数据集（labelImg）→ 训练（YOLO）→ 推理
- 适合识别「血条、敌人、可拾取物」等会变动的目标

### 4. 坐标映射

- 识别出目标在截图中的像素坐标 → 换算成屏幕/游戏坐标
- 关键：**窗口位置偏移 + 缩放比**换算，避免全屏/窗口化差异导致偏移
- 对需要「移动瞄准」的场景，还需结合目标速度做**提前量**（预测运动）

### 5. 输入注入

- 键盘/鼠标模拟：参考[游戏自动化开源参考](游戏自动化开源参考.md)中的 IbInputSimulator（驱动级）
- 或硬件执行层（逆战未来的 Minke ESP32-S3 硬件层）直接产生真实 HID 输入

---

## 三、实操建议（对照逆战未来）

1. **先模板匹配后 YOLO**：UI 固定的部分（图标、按钮）用模板匹配即可；动态目标再上 YOLO
2. **帧率与延迟平衡**：识别帧率 ≠ 输入频率，识别 15-20 FPS + 输入 60 次/秒往往足够
3. **ROI 裁剪**：只识别战斗区域，减少计算量、提高稳定性
4. **OCR 辅助**：血量数字/倒计时等用 Tesseract（见开源参考）
5. **日志可观测**：每次识别结果+决策留日志，便于调参和排查
