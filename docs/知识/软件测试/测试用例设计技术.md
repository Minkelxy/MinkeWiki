# 测试用例设计技术（等价类 / 边界值 / 判定表 / 场景法）

[单元测试学习](单元测试学习.md)讲流程和覆盖率，本文讲**怎么系统设计测试用例**——不是拍脑袋写几个，而是有方法覆盖"正常 / 边界 / 异常"。这是嵌入式 / 汽车软件测试的核心技能。

> 一句话：穷尽测试不可能——**要选"最有价值"的用例**，方法让覆盖有依据。

---

## 一、为什么需要测试用例设计技术

- **穷尽测试不可能**——输入空间无限，只能选代表性用例
- 方法让覆盖**有依据**（不是凭感觉）
- 对应[单元测试学习](单元测试学习.md)流程里的"测试用例设计"步骤

## 二、等价类划分（把无限输入分成几类）

- **有效等价类 + 无效等价类**（有效类测一个代表值即可）
- 例：温度传感器输入 0-100℃ → 有效类 `[0,100]`，无效类 `<0` 和 `>100`
- 目标：**每个类至少一个用例** → 用最少用例覆盖最多

## 三、边界值分析（bug 最爱藏在边界）

- 边界值：`min / min±1 / max / max±1 / 0 / 空 / 溢出`
- 例：温度 0℃ 和 100℃ 边界最易错（`if (t >= 0 && t <= 100)` 的边界）
- **与等价类配合**：边界值必测——边界是"刚好对/刚好错"的地方

## 四、判定表（多条件组合）

- 条件 / 动作表：N 个条件 → 组合场景
- 适合：**多条件逻辑**（如故障处理：过流 & 过温 & 使能 → 停 PWM）
- 去冗余：只列有效组合，别全组合爆炸

## 五、场景法（业务流程）

- 按用户操作流程设计用例（正常流 + 备选流）
- 适合：**状态机 / 业务流程**（RTOS 任务、AUTOSAR 状态切换）
- 结合状态转换图（见[状态机学习](../其他/状态机学习.md)）

## 六、实践建议（嵌入式 / 汽车）

| 项 | 建议 |
|----|------|
| 优先级 | **边界值 > 等价类 > 判定表 > 场景法** |
| 覆盖目标 | 语句 / 分支覆盖率（见[单元测试学习](单元测试学习.md)） |
| 用例模板 | ID / 前置 / 输入 / 预期 / 类型（有效 / 边界 / 异常） |

---

## 七、本轮项目推荐：给你的一段代码写「边界 + 判定表用例」

**推荐做什么**：挑一段你现有的代码（电机控制 / 负载率监测 / RTOS 任务），用**边界值 + 判定表**设计一组测试用例，跑起来验证"边界值是否真易错"。

**为什么值得做**：
- **测试用例设计是测试的核心技能**，但光看不练不会；
- 从**自己代码**入手最实在——边界值最容易出 bug，一试便知；
- 和[单元测试学习](单元测试学习.md)（Tessy / 覆盖率）配套，是软件测试子域的**实操闭环**。

**具体怎么做**：
1. 选一个函数，列输入范围 → 等价类 + 边界值
2. 有多个条件 → 画判定表
3. 设计用例（按模板），用 Tessy 或手写测试跑起来
4. 记录边界值是否真的容易出错

**产出**：一组「边界值 + 判定表」测试用例 + 实测结果 → 进软件测试子域，是测试用例设计的第一个实操成果。
