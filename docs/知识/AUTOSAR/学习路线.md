## 二、推荐进阶顺序（5 步）

### 第 1 步：通信栈（COM → PduR → CanIf → CAN）

- **学什么**：一条 CAN 报文从应用层到物理总线的完整路径（COM 收发 → PduR 路由 → CanIf 抽象 → CAN 驱动）
- **为什么**：这是 AUTOSAR 的骨架——**把你在[现场总线](../现场总线/README.md)学的 CAN 知识接进 AUTOSAR**，从"会 CAN"到"懂 CAN 在 AUTOSAR 里怎么跑"
- **怎么练**：对照你 CANopen FOC 项目的收发路径，画出在 AUTOSAR 里对应哪几层

### 第 2 步：诊断栈（DCM / Dem / Dlt）

- **学什么**：UDS 诊断服务（读取 DID、读写数据、故障码 DTC）、Dcm 到应用层的路由
- **为什么**：车厂项目几乎都带诊断，是 MCAL/BSW 之外最常接触的部分
- **怎么练**：用 can-utils 模拟诊断请求，观察响应链路

### 第 3 步：服务层与存储（NvM / 复杂驱动）

- **学什么**：NvM 非易失存储管理、复杂驱动（CDD）的用法
- **为什么**：标定、故障记录、断电保存全靠 NvM；CDD 是摆脱"纯标准配置"的分水岭

### 第 4 步：RTE 与代码生成（上到应用层）

- **学什么**：RTE 如何连接 SWC 与 BSW，配置工具（EB tresos / ISOLAR 等）怎么生成代码
- **为什么**：从"配 MCAL"升级到"配整个工程"，才真正会用 AUTOSAR 干活
- **怎么练**：把 MCAL 配置指南的工程，往上补通信栈和 RTE，跑通一条端到端报文

### 第 5 步：功能安全深化（ISO 26262 / ASIL）

- **学什么**：ASIL 等级、安全机制（诊断/冗余/看门狗）、FuSa 与 AUTOSAR 的关系
- **为什么**：安全件才有 ASIL 要求，这是[软件功能安全学习](软件功能安全学习.md)的延伸，也是车载工程师的加分项

---

## 三、学习建议总结

- **顺序**：通信栈 → 诊断 → 存储/复杂驱动 → RTE → 功能安全
- **抓手**：每步都"画一条数据链路 + 调一次真实工程"，别只看配置界面
- **复利**：第 1 步接上你已会的 CAN；后面每步都建立在前面之上
- **工具**：开源参考（autoas 等，见[知识库开源参考](../开源参考项目.md)）+ 你能拿到的商用工具链
