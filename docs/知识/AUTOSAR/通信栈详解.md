# AUTOSAR 通信栈详解

一条报文从**应用层到总线的完整路径**——AUTOSAR 通信栈的骨架。承接[AUTOSAR学习路线](学习路线.md)第 1 步与[现场总线](../现场总线/README.md)的 CAN/LIN 知识。

---

## 一、通信栈分层（从高到低）

| 层 | 职责 | 例子 |
|----|------|------|
| **COM** | 应用收发信号、打包/解包 | 应用读写一个"车速"信号 |
| **PduR** | 路由：把 PDU 转到对应接口层 | 转给 CAN 还是 LIN |
| **接口层** | 协议抽象 | CanIf、LinIf、EthIf |
| **驱动层** | 访问具体硬件 | CAN 驱动、LIN 驱动 |

> 关键理解：**上层不管总线类型**——COM 只收发信号，具体走 CAN 还是 LIN 由 PduR 路由决定。

## 二、发送路径（应用 → 总线）

```
应用（写信号）
  → COM（信号打包成 PDU）
  → PduR（查路由表，转给 CanIf）
  → CanIf（加 CAN 帧头/缓冲）
  → CAN 驱动（访问收发器）
  → CAN 总线
```

## 三、接收路径（总线 → 应用）

```
CAN 总线
  → CAN 驱动（收帧）
  → CanIf（解析、去帧头）
  → PduR（路由给 COM）
  → COM（解包成信号）
  → 应用（读到信号）
```

> 发送/接收是**镜像**：接收把"帧→信号"，发送把"信号→帧"。

## 四、关键概念

| 概念 | 说明 |
|------|------|
| **PDU** | 协议数据单元，接口层之间传输的数据单位 |
| 信号（Signal） | 应用能读写的具体数据（如车速、温度） |
| 信号组 | 若干信号打包成一个 PDU |
| **PduR 路由表** | 配置 PDU 走哪个接口层的映射表 |

> 配置工具（EB tresos 等）里主要就是在配这些：**信号→PDU→路由→接口**。

## 五、与底层知识的关系

- 通信栈的"物理细节"（帧格式、仲裁）就是你已学的[现场总线](../现场总线/README.md)内容
- AUTOSAR 把底层**抽象**掉：应用只碰信号，不碰位和帧——这正是 AUTOSAR 的价值
- 学完这条链路，[现场总线协议对比分析](../现场总线/现场总线协议对比分析.md)的选型才落地

## 六、实践建议

1. **画一条报文路径**：拿你 CANopen FOC 项目的收发，画出在 AUTOSAR 里对应 COM → PduR → CanIf → CAN 驱动哪几层
2. 在 MCAL 配置工程里，找通信栈的配置项（PDU、信号、路由）对照
3. 用[知识库开源参考](../开源参考项目.md)的 autoas 看一个现成实现
