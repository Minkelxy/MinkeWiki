# AUTOSAR 诊断栈详解

UDS 诊断服务在 AUTOSAR 里的完整路径——对应[AUTOSAR学习路线](学习路线.md)第 2 步（诊断栈）。

---

## 一、为什么需要诊断

| 场景 | 用途 |
|------|------|
| 售后 | 读取故障码、定位问题 |
| 产线 | 刷写、标定、下线检测 |
| OBD | 排放/法规检查 |

> 诊断是汽车软件**必备功能**，也是 MCAL/BSW 之外最常接触的部分。

## 二、诊断协议：UDS（ISO 14229）

UDS 是一套标准诊断服务，常用：

| 服务 | 作用 |
|------|------|
| 0x22（读取 DID） | 读数据标识符（电压、温度等） |
| 0x2E（写入 DID） | 写数据 |
| 0x19（读 DTC） | 读故障码 |
| 0x14（清 DTC） | 清故障码 |
| 0x10（会话切换） | 进入编程/扩展会话 |
| 0x27（安全访问） | 解锁（写入前鉴权） |

> 一条诊断请求 = 服务 ID + 参数，响应 = 肯定/否定应答码。

## 三、AUTOSAR 诊断栈分层

| 模块 | 职责 |
|------|------|
| **Dcm**（诊断控制管理） | 收诊断请求、路由给应用、组织响应 |
| **Dem**（故障管理） | 存/读/清故障码 DTC |
| **Dlt**（日志） | 诊断日志记录 |
| PduR | 把诊断 PDU 路由给诊断栈（见[通信栈](通信栈详解.md)） |

> 关键理解：诊断请求和普通报文走**同一条通信栈**（CanIf → PduR），只是到 PduR 后路由给 Dcm 而非 COM。

## 四、诊断流程

```
上位机/诊断仪 → CAN 发送诊断请求
  → 通信栈（驱动→CanIf→PduR）
  → Dcm（识别服务、校验会话/安全访问）
  → 应用/ Dem（执行、生成响应）
  → 响应沿原路径返回
```

- 会话管理：默认/扩展/编程会话，不同会话开放不同服务
- 安全访问：写入/刷写前要解锁（种子-密钥鉴权）

## 五、实践建议

1. 用 [can-utils](../开源参考项目.md)（`cansend`/`candump`）模拟发一条 0x22 诊断请求，看响应
2. 对照 MCAL 工程，找 Dcm/Dem 的配置（服务表、DTC 表）
3. 画一条"诊断请求→响应"的完整路径，理解它与普通报文的异同
