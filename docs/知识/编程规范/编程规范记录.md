## 风格
### C模块文件头要求
每一个C/H文件都应有文件头。
文件头包括以下组成部分：版权声明、文件名、项目／产品名称、标题名称、作者、功能描述、约束、变更历史等。
下面的模板待完善
```c
/*
 *  File Name:      <文件名>
 *  Project Name:   <项目名称>
 *  Title:          <标题名称>
 *  Author:         <作者>
 *  Description:    <功能描述>
 *  Constraints:    <约束>
 *  Change History: <变更历史>
 */
```
### C函数头要求
每一个C 函数都应有函数头。

 函数头包括以下组成部分：函数名、简要描述、输入变量、输出变量、约束等 
 ```c
/*
 *  Function Name:  <函数名>
 *  Description:    <简要描述>
 *  Input:          <输入变量>
 *  Output:         <输出变量>
 *  Constraints:    <约束>
 */
```
风格保持个人统一和集体统一，避免出现不一致。

### 包含文件
头文件按以下顺序，由三部分内容构成：
文件头；
预处理块（如果存在）； 
函数和变量声明等（如果存在）。

所有包含文件都应加后缀.h。

用 #include “filename.h” 格式来引用头文件（编译器将从用户的工作目录开始搜索），引用的标准库文件放入到用户工作目录下。


### 定义文件
定义文件按以下顺序，由三部分内容构成：
文件头；
对一些头文件的引用（如果存在）；
程序的实现体（包括数据和代码）（如果存在）；

源代码中不允许出现无用变量。  

### 代码行
一行代码只做一件事情，比如只定义一个变量，或只写一条语句，以使代码易阅读，并且便于写注释。

较长语句要换行，长的语句（>80 字符）要分成多行书写。  

### 空格和缩进
对于嵌套语句，每一层嵌套缩进4 个空格，不允许使用“tab”键缩进

### 对齐
表示程序结构开始和结束的括弧‘{’和‘}’应独占一行并且与程序结构的第一个字符对齐。起始和结束括弧{}内的代码应缩排成一个等级，当内嵌括弧时，括弧内的代码应随内嵌括弧继续缩进。  

### 注释
注释缩进格式应与代码的缩进级别一致。
注释的位置可以放在代码的上方或右方，不可放在左方、下方。
建议使用英文注释。
不允许在一行代码或表达式的中间插入注释。

代码必须有适当的注释。 
建议至少确保下列内容要给予注释。
（1）全局变量 或认为有必要的 局部变量定义或 声明，说明：在对变量定义或声明的同时，应对其含义、作用及取值范围进行注释说明。同时，若有必要还应说明与其它变量的关系。
（2）语句块的结束 ，即 ”}” 处

注释的内容要清楚、明了，含义准确，防止注释的二义性。
【规则解释】错误的注释不但无益，反而有害


注释应当是在代码的功能、意图层面上进行注释，提供额外的、有效的信息。
【规则解释】注释的目的是解释代码的目的、功能和采用的方法，提供代码以外的信息，帮助读者理解代码，防止没必要的重复注释信息


通过对函数、变量、结构等正确的命名以及合理的组织代码的结构，使代码成为自注释的。
【规则解释】清晰准确的函数、变量等的命名，可增加代码的可读性，并可以减少不必要的注释


数据结构定义 ( 包括数组、结构类枚举等 ) ，如果其命名不是充分自注释的，必须加以注释。


对自定义数据类型进行恰当命名，使它成为自描述性的，以提高代码可读性。

【规则解释】使用自定义类型，可以弥补编程语言提供类型少、信息量不足的缺点，并能使程序清晰、简洁。

对自定义数据类型进行恰当命名，使它成为自描述性的，以提高代码可读性。

【规则解释】使用自定义类型，可以弥补编程语言提供类型少、信息量不足的缺点，并能使程序清晰、简洁。


### 命名
禁止使用汉语拼音命名
宏代表常数（量）或者常数（量）表达式时，其名称一律采用全大写

/* macro definition */
/* Write mode */
#define TLE9262_OP_MODE_WRITE   0x80u  
/* Read mode */  
#define TLE9262_OP_MODE_READ    0x00u   
/* Read and Clear Status */  
#define TLE9262_OP_MODE_READ_CLR_ST    0x80u     


文件命名：统一格式为<Module name>A.B
【规则解释】
A:标识一个模块不同文件的属性：


文件命名：统一格式为<Module name>A.B
【规则解释】
Module name：模块缩写，2-8个字母，每个单词第一个字母大写，后面字母小写；
A:标识一个模块不同文件的属性：
B:c或者h  

示例：
CanTp_Cbk.h
CanTp_Cfg.h
CanTp_PBcfg.c

命名：英文缩写可参见《汽车软件术语定义规范》


变量名按下表规则添加前缀（绿色表示可省略）

模块自定义的数据类型，应加上前缀<Module name>_，这样可以避免不同模块之间可能使用相同的名称

全局变量：g<Module name>_<Variable name>
局部变量不允许加Module name;

函数命名：<Module name>_FunctionName


宏命名：<Module name>_MacroName


除0、用来表示递增和递减的数值1及其他允许使用的数值外，禁止直接使用数值，所有数值应定义为常量或用#define定义，以便于维护和升级

/* macro definition */
#define IMMO_ID_LENGTH_BYTE                       (4u)
#define IMMO_PSWT_LENGTH_BYTE                 (4u)
#define IMMO_PSWB_LENGTH_BYTE                 (4u)
#define IMMO_RKE_SKH_LENGTH_BYTE           (2u)
#define IMMO_RKE_SKL_LENGTH_BYTE            (4u)

其他
所有涉及到硬件的变量应设为动态变量(volatile)。
如果使用指针，在使用指针之前，必须赋给指针一个地址值。
【规则解释】一些编译器会在编译时给指针随机赋予一个地址，这就意味着指针可能会指向代码空间。给未初始化的指针赋值，其结果无法预计，而且，可能会带来严重后果。
函数定义时的参数不应超过7个，如果参数太多可以将多个参数组合成一个结构体。
软件工程编译后不能有warning。
