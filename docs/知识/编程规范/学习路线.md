## 二、推荐进阶顺序（5 步）

### 第 1 步：规范背后的"为什么"

- **学什么**：未定义行为（UB）、实现定义行为、可移植性问题——比如 `int` 位宽、有符号溢出、`sizeof` 依赖
- **为什么**：规则本质是"避开这些坑"——懂了坑，规则就是自明的
- **怎么练**：挑 5 条你记过的规范，找到它对应的 UB/陷阱（如"避免隐式转换"→ 整型提升陷阱）

### 第 2 步：MISRA C 深入（嵌入式重点）

- **学什么**：MISRA C 的强制性规则（禁用动态内存、限制 goto、强制括号等）
- **为什么**：嵌入式/汽车安全件（你的 AUTOSAR 方向）常强制 MISRA 合规
- **怎么练**：拿你的[负载率监测软件](../../制作/负载率监测软件.md)或电机代码，对照 MISRA 规则自查

### 第 3 步：静态分析落地

- **学什么**：用 [cppcheck](https://github.com/cppcheck-opensource/cppcheck)（★6.7k）/ Polyspace 自动查规范违规（见[软件测试学习路线](../软件测试/学习路线.md)）
- **为什么**：人工查规范不可靠，静态分析是唯一可行的落地方案
- **怎么练**：给现有项目跑 cppcheck，把致命告警清零，设成质量门

### 第 4 步：命名 / 注释 / 架构规范

- **学什么**：命名风格（前缀/大小写）、注释该写什么（为什么 > 是什么）、模块边界
- **为什么**：规范很大一部分是**可读性和可维护性**，比语法更重要
- **怎么练**：把已有代码的命名/注释按规范过一遍，体会"读得顺"的差别

### 第 5 步：团队规范落地

- **学什么**：规范文档化、检查清单、CI 强制、评审流程
- **为什么**：规范不落地 = 没规范；要靠工具和流程强制，不靠自觉
- **怎么练**：把你的[编程规范记录](编程规范记录.md)整理成一页 checklist，接进 CI（见[软件测试学习路线](../软件测试/学习路线.md)）

---

## 三、学习建议总结

- **顺序**：为什么 → MISRA → 静态分析 → 命名/注释 → 团队落地
- **抓手**：每一步都落到**现有代码**（负载率/电机/RTOS），别空记规则
- **复利**：规范能力同时服务你的 AUTOSAR 项目和[软件测试学习路线](../软件测试/学习路线.md)的静态分析部分
