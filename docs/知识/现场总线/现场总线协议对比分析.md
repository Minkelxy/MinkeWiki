# 现场总线协议对比分析

车载现场总线横向对比，接续 [CAN](CAN总线协议详解.md) 与 [LIN](LIN总线协议详解.md)。看完本文，你能根据**速率、确定性、成本**给一个应用选对总线。

---

## 一、对比总览

| 协议 | 最高速率 | 拓扑 | 成本 | 典型应用 |
|------|---------|------|------|---------|
| **LIN** | 20 kbps | 单线主从 | 最低 | 车窗、座椅、后视镜 |
| **CAN** | 1 Mbps | 双线多主 | 中 | 动力、车身、诊断 |
| **CAN FD** | 8 Mbps | 双线多主 | 中 | 现代车载（数据段提速） |
| **FlexRay** | 10 Mbps | 双通道 | 高 | 线控、底盘（安全关键） |
| **车载以太网** | 100M-1G | 星型 | 高 | ADAS、域控制器、诊断 |

## 二、关键差异维度

### 1. 确定性（实时性保证）

| 协议 | 机制 | 确定性 |
|------|------|--------|
| CAN | 事件驱动 + 非破坏性仲裁 | 中（最坏时间可算） |
| LIN | **主节点调度表** | 高（时间驱动） |
| CAN FD | 同 CAN | 中 |
| FlexRay | 时间触发（TDMA）+ 事件 | **最高** |
| 以太网 | 尽力而为（AVB/TSN 增强） | 低（TSN 后提升） |

### 2. 容错与冗余

- **LIN**：无冗余，成本优先
- **CAN**：单通道，故障节点隔离（见 [CAN 错误处理](CAN总线协议详解.md)）
- **FlexRay**：**双通道冗余**，适合线控/安全
- **以太网**：可配冗余链路，但复杂度高

### 3. 带宽与演进

- CAN 1Mbps 是旧瓶颈 → **CAN FD 数据段 8Mbps**、**以太网 Gbps** 解决大带宽
- 自动驾驶/OTA 的大数据量只有以太网扛得住

## 三、车载网络架构演进

**传统分层**（成本导向）：

```
CAN 骨干（动力/底盘/诊断）
   ├── LIN 支线（车窗/座椅）
   └── CAN 支线（车门/灯）
```

**现代域控**（带宽/算力导向）：

```
车载以太网骨干（域控制器/ADAS/中央网关）
   ├── CAN FD 域内总线（动力域）
   ├── LIN（低速车身）
   └── FlexRay（线控底盘，安全件）
```

> 趋势：以太网做骨干，CAN FD 做域内，LIN 继续做末端——**不是取代，是分层分工**。

## 四、选型建议

| 场景 | 推荐 |
|------|------|
| 车窗/座椅/开关 | **LIN**（最便宜） |
| 动力/车身/诊断 | **CAN / CAN FD**（性价比最佳） |
| 线控/转向等安全件 | **FlexRay**（双通道确定性） |
| ADAS/视频/OTA/大数据 | **车载以太网** |
| 现代整车 | 以太网骨干 + CAN FD + LIN 混合 |

## 五、与 AUTOSAR 的关系

- 每种总线在 AUTOSAR 里都有对应通信栈模块（CanIf/CAN、LinIf/LIN、FlexRayIf/FlexRay、EthIf/以太网），上层统一走 PduR + COM
- 学完各总线，正好衔接 [AUTOSAR学习路线](../AUTOSAR/学习路线.md) 的通信栈部分
