# CAN FD 详解

CAN FD（Flexible Data-rate）详解——CAN 2.0 的进化版。承接[CAN总线协议详解](CAN总线协议详解.md)（原文第 5 章只概述，这里展开）。

---

## 一、为什么需要 CAN FD

| CAN 2.0 的痛点 | CAN FD 的答案 |
|---------------|--------------|
| 数据场最多 **8 字节**（带宽瓶颈） | 最多 **64 字节** |
| 速率固定（最高 1Mbps） | **数据段提速**（2-8 Mbps） |
| CRC 保护有限 | CRC 增强 |

> 现代车载数据量暴涨（OTA、诊断、多传感器），CAN 2.0 的 8 字节/1Mbps 不够用了。

## 二、核心改进（三大件）

### 1. 数据场扩容
- **8 → 64 字节**：一条报文装更多数据，减少总线占用

### 2. 双速率
- **仲裁段**：保持原速率（1Mbps，保证仲裁兼容）
- **数据段**：提速到 2-8 Mbps（只在传输数据时提速）

```
仲裁段(慢) → 数据段(快) → CRC/ACK(慢)
```

### 3. CRC 增强
- 数据段用更强的 CRC，降低漏检率（大报文更可靠）

## 三、与 CAN 2.0 对比

| 维度 | CAN 2.0 | CAN FD |
|------|---------|--------|
| 数据场 | 8 字节 | **64 字节** |
| 速率 | 1Mbps 固定 | 数据段 2-8Mbps |
| CRC | 15 位 | 增强（分段） |
| 帧格式 | 标准/扩展 | 兼容 + FDF 标志位 |
| 物理层 | 双线差分 | **兼容** |

> 关键：**物理层兼容**——同一总线/收发器可混跑 CAN 2.0 和 CAN FD（FD 用 FDF 标志位区分）。

## 四、兼容与部署

- **物理层不变**：终端电阻、双线、收发器可复用
- **混合网络**：CAN 2.0 节点和 CAN FD 节点可共存（FD 节点需支持仲裁段同速）
- 控制器：现代 MCU 的 CAN 外设普遍支持 FD（AUTOSAR 的 CanIf 也支持）

## 五、应用场景

| 场景 | 为什么用 FD |
|------|------------|
| OTA 刷写 | 大数据量，FD 提速 |
| 诊断（UDS） | 大诊断包 |
| 传感器数据 | 多通道数据一次传 |
| 现代域控 | 域内总线用 FD（见[现场总线对比](现场总线协议对比分析.md)） |

> 演进趋势：CAN 2.0 逐渐被 CAN FD 取代，新车型域内多用 FD；但低成本低速段仍用 LIN。
